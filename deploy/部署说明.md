# 小晗复习 Agent：Ubuntu + Docker 部署

部署包包含代码、Python 依赖锁文件、Node 依赖锁文件、Dockerfile 与 Compose。附带数据版还包含资料库快照、上传文件和教程笔记。Mac 的 `.venv` 与 `node_modules` 不进入部署包，Docker 会为 Ubuntu 的 CPU 架构重新安装对应依赖。不需要 GPU。

## 1. 上传部署包与配置

在 Mac 终端执行，把 `ubuntu@你的服务器IP` 替换为实际 SSH 账号和地址：

```bash
scp /Users/williams/Documents/Codex/2026-11-09/longchain-rag-milvus-mcp-prompt-github/outputs/xiaohan-review-agent-ubuntu.tar.gz ubuntu@你的服务器IP:~/
scp /Users/williams/Documents/Codex/2026-11-09/longchain-rag-milvus-mcp-prompt-github/outputs/xiaohan-review-agent-ubuntu.tar.gz.sha256 ubuntu@你的服务器IP:~/
scp /Users/williams/Conda/xiaohan-review-agent/.env ubuntu@你的服务器IP:~/xiaohan-review-agent.env
```

真实 `.env` 单独通过 SSH 上传，不会写入镜像。它已有 DeepSeek、百炼与 PostgreSQL 的配置，不要再用示例配置覆盖。

## 2. 在 Ubuntu 解压并启动

```bash
ssh ubuntu@你的服务器IP
docker compose version
cd ~
sha256sum -c xiaohan-review-agent-ubuntu.tar.gz.sha256
mkdir -p ~/apps
tar -xzf xiaohan-review-agent-ubuntu.tar.gz -C ~/apps
cd ~/apps/xiaohan-review-agent
mv ~/xiaohan-review-agent.env .env
chmod 600 .env
docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:8080/api/health
```

账号没有 Docker 权限时，在 `docker` 命令前加 `sudo`。首次构建要下载基础镜像和依赖。服务器需要能访问 Docker Hub、GHCR、PyPI、npm、模型 API 和 PostgreSQL。如果本机 Docker 的代理异常，可以直接在 Ubuntu 构建，避免搬运 Mac 架构镜像。

`docker compose ps` 应显示后端健康、前端运行；健康接口应出现 `"memory_backend":"PostgreSQL"`、`"history_enabled":true`，附带数据部署还应显示原有资料数量。

## 3. 从电脑打开页面

目前系统供单人使用，没有账号登录，默认只监听服务器的 `127.0.0.1:8080`。在 Mac 新开终端建立 SSH 隧道：

```bash
ssh -N -L 18080:127.0.0.1:8080 ubuntu@你的服务器IP
```

保持这个终端运行，在浏览器打开 <http://127.0.0.1:18080>。无需开放 8010、5174 或 8080 的公网入站端口。

需要域名或直接从公网访问时，先给站点配置 HTTPS 与访问认证，再在服务器 `.env` 中设置 `XIAOHAN_BIND_HOST=0.0.0.0` 并重建前端容器；应用自身目前没有用户隔离。

## 4. 数据保存位置

| 内容 | 保存位置 |
| --- | --- |
| 会话列表、消息、Agent checkpoint | 原 `DB_URL` 指向的 PostgreSQL |
| Milvus Lite 资料向量与 SQLite 资料清单 | 服务器项目的 `runtime/data/` |
| 上传原文件 | `runtime/uploads/` |
| 可供一键导入的教程笔记 | `runtime/tutorial/` |
| 模型和数据库密钥 | 服务器项目的 `.env` |

Compose 把这些目录挂载进后端，重建镜像或执行 `docker compose down` 不会删除它们。不要删除 `runtime` 目录。附带数据包已保留原来的资料 ID，因此历史会话还能关联原资料；不需要重新向量化。

容器内后端使用单个进程运行 Milvus Lite，MCP 仍是后端内部拉起的 Python stdio 进程，不需要单独开放 MCP 端口。前端由 Nginx 提供静态文件，并把 `/api` 请求代理到后端，不再运行 Vite 开发服务。

服务器沿用原 PostgreSQL 连接串，容器需要能够连接该数据库。若 PostgreSQL 就在同一台 Ubuntu 上，也可把连接串中的主机改为 `host.docker.internal`；Compose 已配置这个主机名。容器里的 `localhost` 指向容器本身。

## 5. 日常维护

```bash
# 查看日志
docker compose logs -f --tail=100 backend frontend

# 修改 .env 后重新加载配置
docker compose up -d --force-recreate backend

# 停止应用，数据保留
docker compose down

# 代码更新后重新构建
docker compose up -d --build
```

后续升级请生成不带 `--with-data` 的代码包，解压时排除 `runtime/`，保留服务器现有数据：

```bash
tar -xzf 新代码包.tar.gz -C ~/apps --exclude='*/runtime' --exclude='*/runtime/*'
cd ~/apps/xiaohan-review-agent
docker compose up -d --build
```

备份资料库时先停止后端，避免复制写入中的数据库：

```bash
docker compose stop backend
tar -czf ~/xiaohan-runtime-backup.tar.gz runtime
docker compose start backend
```

PostgreSQL 需要另行备份，这个 tar 包只包含本项目的本地资料数据。

## 6. 重新在 Mac 打包

在 PyCharm 或启动终端中停止后端，再运行：

```bash
cd /Users/williams/Conda/xiaohan-review-agent
python3 scripts/package_deploy.py \
  --output /Users/williams/Documents/Codex/2026-11-09/longchain-rag-milvus-mcp-prompt-github/outputs/xiaohan-review-agent-ubuntu.tar.gz \
  --with-data \
  --tutorial-dir /Users/williams/Conda/langchain_tutorial
```

打包后重新启动本机后端：

```bash
cd /Users/williams/Conda/xiaohan-review-agent/backend
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8010
```

代码包本身不包含已安装的 Linux 依赖。`docker compose up -d --build` 会在服务器构建完整运行环境；如果服务器不能访问镜像仓库或依赖站点，需要在相同 CPU 架构的机器上先构建镜像，再使用 `docker save` / `docker load` 离线传输。
